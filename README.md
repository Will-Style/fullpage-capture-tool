# Fullpage Capture

URL を入力すると、Web サイトをキャプチャできるローカル Web アプリです。

- **静止画** — ページ全体を 1 枚の画像に。**Retina 解像度・指定した画面幅・無劣化**
- **スクロール動画** — 1 画面ずつスクロールしては静止する紹介動画と、場面をランダムに抜いたダイジェスト
- **動画に枠を付ける** — 手持ちの動画を指定サイズのキャンバス中央に置き、周囲を背景色で塗る

## 必要なもの

- Node.js
- **ffmpeg**（動画機能のみ）。`brew install ffmpeg`。別の場所にあるなら `FFMPEG_PATH` で指定できます

## 起動

```bash
cd ~/Workspace/DEVELOP/fullpage-capture
npm start
```

ブラウザで <http://localhost:3838> を開きます。停止は `Ctrl+C`。

ポートを変えたい場合は `PORT=4000 npm start`。

## 使い方（静止画）

1. 「静止画」タブを選ぶ
2. URL を入力（`https://` は省略可）
3. 画面幅をプリセットから選ぶか、数値を直接入力（320〜3840px）
4. 解像度を選ぶ（**2x が Retina**、3x も可）
5. 「キャプチャ」→ プレビューを確認 → 「ダウンロード」

### 詳細設定

| 項目 | 説明 |
|---|---|
| ローディングが明けるまで待つ | 既定 ON。後述 |
| 追加待機 (ms) | 読み込み完了後の待ち時間。アニメーション付きのページで長めにすると安定します |
| ビューポート高さ | 内部のブラウザウィンドウの高さ。`100vh` を使うページの見え方が変わります |
| JPEG 品質 | JPEG 選択時のみ表示。1〜100 |
| 固定ヘッダー・追従要素を解除する | `position: fixed` / `sticky` を解除。静止画では ON のままを推奨（後述） |

### ローディングが明けるまで待つ

オープニングアニメーションのあるサイトでは、**ローディング画面がフェード中の状態がそのまま写り込む**ことがあります。アニメーションを止める処理（`freezeAnimations`）が、フェード途中の不透明度で固定してしまうためです。

そこで撮影前に、画面が視覚的に落ち着くまで待ちます。ビューポートを 32×32 のグレースケールに潰した「指紋」を 0.35 秒ごとに比べ、2 回続けて変化しなければ確定します。動画の自動再生など永久に変わり続けるページのために **10 秒で必ず打ち切ります**（打ち切った場合は結果に明記されます）。

実測（willstyle.co.jp）では待機なし 6.0 秒 → 待機あり 8.6 秒で、ローディングの白いオーバーレイと「100 %」表示が消えました。

## 使い方（スクロール動画）

「スクロール動画」タブで URL と条件を指定し、「動画を作成」を押します。本編とダイジェストが同時に作られ、その場で再生・ダウンロードできます。

**実ブラウザを実時間で収録します。** 追従ヘッダー・スクロール連動アニメーション・自動再生動画・時間ベースのループアニメが、すべて本来の挙動のまま写ります。解像度はビューポート相当です。

### 動きの間合い

移動時間 **1.2 秒**・静止時間 **0.6 秒** は固定です（`video.js` 冒頭の定数）。1 ステップ 1.8 秒になります。

1 回に進む量だけ選べます。刻みを細かくするほどステップ数が増え、尺が伸びます。

| 設定 | ビューポート 828px のとき | 高さ 11,945px のページでの本編 |
|---|---|---|
| 6 割 | 497px | 23 ステップ / 42.0 秒 |
| 8 割 | 662px | 17 ステップ / 31.2 秒 |
| **1 画面**（既定） | 828px | 14 ステップ / 25.8 秒 |

### fps とカクつき

**Playwright の録画は 25fps 固定です。** これはこちらで変えられません。

出力を 25 以外にすると、ffmpeg が足りないコマを複製して尺を合わせます。複製は等間隔に入らないため、**Parallax のように動き続ける要素がカクついて見えます**。既定を 25fps にしているのはこのためです。

同じ素材（Parallax テストページ）での実測です。

| 出力 | 動きのコマ | うち重複コマ | 割合 |
|---|---|---|---|
| 録画そのまま（25fps） | 248 | 5 | 2% |
| → 25fps に変換 | 248 | 5 | **2%** |
| → 30fps に変換 | 249 | 52 | 21% |

| 選択肢 | 内容 |
|---|---|
| **25**（既定） | 録画元と同じ。複製ゼロ |
| 50 | 各コマをちょうど 2 回ずつ複製。等間隔なので破綻はしないが情報は増えない |
| 30 / 60 | 納品仕様で必要な場合のみ。複製が不規則に入る |

スクロール自体は表示のリフレッシュ（60〜120Hz）ごとに位置を補間して動かしているので、出力 fps と切り離してなめらかに進みます。

### 画面サイズ

動画タブの既定は **1512 × 828**（書き出しに使うノート PC 相当）。静止画タブは 1440 × 900 です。
タブごとに独立して保持するので、切り替えても互いの設定を壊しません（URL だけは引き継ぎます）。

### イージング

1 ステップの移動をどんな速度変化で行うかを選べます。19 種類あり、いずれも行き過ぎ（オーバーシュート）はしません。

| 系統 | 動き | 収録している種類 |
|---|---|---|
| `linear` | 等速。機械的 | — |
| **Out** | 急発進して減速する＝**慣性** | Sine / Quad / Cubic / **Quart（既定）** / Quint / Expo |
| **InOut** | ゆっくり動き出しゆっくり止まる | 同上 6 種 |
| **In** | ゆっくり動き出して加速する | 同上 6 種 |

同じ系統では Sine → Quad → Cubic → Quart → Quint → Expo の順に効きが強くなります。`easeOutSine` が最も穏やか、`easeOutExpo` が最も急な減速です。

> **注意** 減速の急なイージング（`easeOutQuint` / `easeOutExpo`）は 1 コマあたりの移動量が大きくなります。動画にはモーションブラーがないため、30fps ではカクついて見えることがあります。その場合は **60fps** にしてください。

### 冒頭の静止（イントロを写す）

`冒頭の静止 (秒)` に秒数を入れると、スクロールを始める前にその秒数だけページを静止させます。オープニングアニメーションのあるサイトで使います。

準備段階で一度ページ全体をスクロールする（遅延読み込み画像の展開）ため、その時点でイントロは再生され切っています。そこで**収録の直前にページを読み込み直し**、アニメーションを最初から流します。

秒数はサイトごとに実測して決めてください。足りないとイントロの途中でスクロールが始まります。目安として、オープニングが 3.5〜4 秒あるサイトなら 5 秒程度です。

- ダイジェストにも別途設定できます（後述）
- 読み込み直しの基準は `load` です。それより前に始まるアニメーションは頭が欠けることがあります
- 指定した秒数は**尺の上限には含めず加算**します

### 尺の決まり方

指定するのは**尺の上限**で、実際の長さはページの高さから決まります。

```
尺 ≒ 冒頭の静止 + 静止 0.6 + ステップ数 × 1.8 秒
ステップ数 = ページのスクロール可能量 ÷ ビューポート高さ
```

上限を超える場合は移動・静止時間を比例で詰めて収めます（下限は移動 0.3 秒・静止 0.25 秒）。詰めた場合は結果画面に明記されます。それでも超えるときは超過を許容し、実尺を返します。

短いページでは指定より短くなります（無理に引き伸ばしません）。

### ダイジェスト

本編とは別に収録し、**場面をランダムに選んでハードカットでつないだ**ダイジェストを作ります。早送りではありません。

**1 場面の動きは本編とまったく同じ**です。移動量（1 画面）・移動時間・静止時間・イージングをすべて共有するため、本編から断片を切り出したように見えます。本編が尺の上限で間合いを詰められた場合も、ダイジェストは同じ値に追従します。

移動量も本編の設定（6 割 / 8 割 / 1 画面）をそのまま使います。**1 場面目は必ずページ先頭**から始まります。2 場面目以降は**層化抽出**で選びます。一様乱数だと選んだ点が固まって同じあたりばかり映るため、残りのスクロール範囲を等分して各区画から 1 点ずつ選ぶ方式です。ページ全体を必ずカバーしつつ、毎回違う絵になります。並びは上から下のまま保つので、ページを辿る流れは崩れません。

| 項目 | 既定 | 内容 |
|---|---|---|
| 尺 | 10 秒 | 上限。1 場面は「移動 1.2 秒＋静止 0.6 秒」で約 1.83 秒なので、10 秒なら 5 場面 |
| 場面数 | 自動 | 自動は尺に入るだけ詰めます。スクロール量が少ないページではさらに減ります |
| 冒頭の静止 | 0 秒 | 本編と同じくイントロを写せます（1 場面目が必ずページ先頭なので成立します）。**尺には加算**され、10 秒＋5 秒なら約 15 秒になります |
| シード | ランダム | 同じ値を入れると**同じ場面が選ばれます**。結果画面に使われたシードが出ます |

#### 引き直し

結果画面のダイジェストに **「ダイジェストを引き直す」** ボタンがあります。押すとダイジェストだけを新しい抽選で撮り直します。

- **本編には一切触れません**（ファイルもそのまま）
- 収録するのはダイジェストの尺ぶんだけなので速く、10 秒のダイジェストで 15 秒ほどです
- 前回のダイジェストは差し替え後に削除されます
- 気に入った抽選はシードを控えておけば再現できます

### 一時ファイル

出力した画像・動画は OS の一時ディレクトリ（`$TMPDIR/fullpage-capture`）に溜まります。動画は 1 本あたり数 MB〜十数 MB になるので、画面下部に**使用量と「一時ファイルを削除」ボタン**があります。

押すとこれまでの出力をすべて消し、ジョブの記録も破棄します（以降そのジョブの URL は 404 になります）。処理中は 409 を返して受け付けません。

### ダイジェストの枠（余白）

ダイジェストだけに余白を付けられます（本編には付きません）。`video-padding-app` の「余白を付ける」と同じ計算です。既定は `1920x1300` / 動画 `90%` / 背景 `#1C1C1A`。

出力ファイル名にはキャンバスサイズが付きます（`…_digest_1920x1300.mp4`）。詳しい計算は後述の「動画に枠を付ける」と同じです。

### 出力形式と WordPress

WebM (VP9) と MP4 (H.264) を同時に出力できます（既定は両方）。

WordPress はコアの許可 MIME に `webm` を含むため **`.webm` をそのままアップロードできます**。
ただし再生可否はブラウザ依存で、Safari は macOS 14.1+ / iOS 17.4+ でないと VP9 WebM を再生できません。
そのため、両方アップロードしてフォールバックさせるのが安全です（結果画面に貼り付け例が出ます）。

```
[video webm="…/example.webm" mp4="…/example.mp4"]
```

同条件で WebM は MP4 の 1/3 前後のサイズになります。

### 所要時間の目安

実時間収録なので、**尺 ＋ 準備と変換**です。ページ高さ 12,000px のサイトで、21 秒の本編（冒頭の静止 5 秒込み）＋ 8 秒の枠付きダイジェストを MP4 で作って **約 90 秒**。

## 使い方（動画に枠を付ける）

「動画に枠を付ける」タブでは、**手持ちの動画ファイル**に余白を付けられます。スクロール動画とは独立していて、どんな動画でも通せます。

1. 動画ファイルを選ぶ
2. キャンバスサイズ・動画の割合・背景色を決める
3. 「枠を付ける」

- **フレームレートと尺は変えません**
- **音声があればそのまま残します**（MP4 は AAC、WebM は Opus。WebM に AAC は入れられないため形式で分けています）
- アップロード上限は 2GB

### 余白の計算

動画はアスペクト比を保ったまま「キャンバス × 割合」の枠に収め、中央に配置して、残りを背景色で塗ります。`yuv420p` のため動画サイズも配置位置も偶数に丸めます。

例）1920×1080 の動画を `1920x1300 / 90%` で変換した場合

- 枠：1728 × 1170 → 横幅が先に接するので動画は **1728 × 972**
- 余白：左右 96px、上下 164px

割合は**辺の比**なので、90% でも面積比は約 75% です。出力は `元の名前_1920x1300.mp4` になります。

## 静止画の 3 つの要件をどう満たしているか

### Retina

Chromium の `deviceScaleFactor` に 2 を指定しています。1x で撮って拡大しているのではなく、**2 倍の密度で実際にレンダリング**しているため、文字・線・画像すべてが本物の高精細です。1440px 幅 × 2x なら実ピクセルは 2880px になります。

### 指定した画面幅

ビューポート幅そのものを指定値に設定しています。CSS のメディアクエリも指定幅で正しく評価されるため、「1440px のときのデザイン」「390px のときのデザイン」を正確に撮り分けられます。動画も同じ仕組みで幅を決めています。

### 画質の劣化がないこと

出力は **PNG（可逆圧縮）** です。撮影から保存まで一度も非可逆変換を通らないため、劣化はゼロです。JPEG を選んだ場合のみ、最後に一度だけ変換します（その際もクロマサブサンプリングを `4:4:4` に固定し、文字の色にじみを防いでいます）。

## 実装で対処している問題

| 問題 | 対処 |
|---|---|
| 長大ページで画像が切れる／失敗する | Chromium のラスタライズ上限（約 16384px）を超える場合、ビューポート単位で分割撮影し `sharp` で結合。2x でも高さ 4 万 px 超を確認済み |
| 遅延読み込み画像が空白になる | キャプチャ前に最下部まで段階的にスクロールして展開し、先頭へ戻す |
| 固定ヘッダーが何度も写り込む | `position: fixed` を `absolute` に、`sticky` を `static` に変換 |
| 撮るたびに絵が変わる | CSS アニメーション・トランジションを停止し、動画を一時停止、キャレットを非表示化 |
| Web フォント適用前に撮れてしまう | `document.fonts.ready` を待機 |
| 広告や解析タグで読み込みが終わらない | `networkidle` は 15 秒でタイムアウトさせて続行 |
| Parallax がカクつく | 録画元 25fps を 30fps へ引き伸ばすとコマが複製される。既定を 25fps に合わせた |
| スクロールが 1 コマ単位で段付く | 表示のリフレッシュごとにタイムラインを補間して位置を渡す |
| ローディング画面が半透明で焼き付く | アニメーションを止める前に、画面が落ち着くまで待つ |
| スムーススクロールで尺が狂う | `scroll-behavior: auto` を強制（動画でもアニメーション自体は止めない） |
| 録画に読み込み中の画が入る | 「ここから本番」と決めた時刻を控え、それ以前を `-ss` で切り落とす |
| 準備中にイントロが再生され切ってしまう | 冒頭の静止を使うときは、収録直前にページを読み込み直す |
| ダイジェストの場面が一箇所に固まる | 一様乱数ではなく層化抽出（範囲を等分し各区画から 1 点） |
| 本編を詰めるとダイジェストと間合いがずれる | ダイジェストは本編のタイムラインを計算し直し、その実値を使う |
| ダイジェストを撮り直すと別物になる | 場面選びをシード付き乱数にし、使ったシードを結果に表示 |
| 大きな動画をアップロードするとメモリを食う | multipart を使わず、生のボディをそのままファイルへ流す |
| WebM に AAC 音声を入れようとして失敗する | 形式で音声コーデックを分ける（MP4 は AAC、WebM は Opus） |
| 尺の計算が壊れると ffmpeg が不可解に落ちる | 秒数の引数は必ず `secArg()` を通し、NaN を 0 に落とす |

## 構成

```
fullpage-capture/
├── capture.js        静止画キャプチャ（Playwright + sharp）
├── video.js          スクロール動画（Playwright + ffmpeg）
├── server.js         Express API とファイル配信
├── public/index.html UI（依存ライブラリなし）
└── package.json
```

API を直接叩くこともできます。

```bash
# 静止画（同期）
curl -X POST http://localhost:3838/api/capture \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com","width":1440,"scale":2,"format":"png"}'
# → {"id":"...", "pixelWidth":2880, "pixelHeight":1800, ...}
# 画像は GET /api/download/:id で取得

# スクロール動画（非同期。すぐ id が返る）
curl -X POST http://localhost:3838/api/video \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com","targetSec":60,"introSec":5,"easing":"easeOutQuart",
       "stepRatio":0.8,"digestSec":10,"digestScenes":0,"digestIntroSec":5,"seed":42,
       "pad":true,"padWidth":1920,"padHeight":1300,"padPercent":90,"padColor":"#1C1C1A",
       "formats":["webm","mp4"]}'
# → {"id":"..."}

# 手持ちの動画に枠を付ける（動画は生のボディで送る）
curl -X POST --data-binary @input.mp4 \
  -H 'Content-Type: application/octet-stream' \
  'http://localhost:3838/api/pad?filename=input.mp4&formats=mp4,webm&padWidth=1920&padHeight=1300&padPercent=90&padColor=%231C1C1A'
# → {"id":"..."}
```

`easing` は `linear` と `ease{In,Out,InOut}{Sine,Quad,Cubic,Quart,Quint,Expo}` の 19 種。
`digestScenes` と `seed` は 0・未指定で自動（シードは毎回ランダム）。`pad` 一式はダイジェストにのみ効きます。

| エンドポイント | 用途 |
|---|---|
| `GET /api/video/:id` | 状態と結果を JSON で取得（枠付けジョブも同じ） |
| `GET /api/video/:id/events` | 進捗を SSE で購読 |
| `POST /api/video/:id/digest` | ダイジェストだけを引き直す。`{"seed":123}` で抽選を指定できる |
| `GET /api/video/:id/file/:key/:format` | 再生用（Range 対応）。`key` は `main` / `digest` / `padded` |
| `GET /api/video/:id/download/:key/:format` | ダウンロード |
| `GET /api/storage` | 一時ファイルの個数と合計バイト数 |
| `POST /api/storage/clear` | 一時ファイルを全削除（処理中は 409） |

## 制限事項

- Basic 認証・ログインが必要なページには未対応です（Cookie 注入を足せば対応可能）
- 無限スクロールのページは、それ以上進めなくなった時点で打ち切ります
- 出力は OS の一時ディレクトリに保存されます。再起動時に消える場合があります
- 動画は CPU と Chromium を占有するため、**同時に 1 本まで**です（処理中の要求は 409 を返します）
- スクロール動画は実時間で収録するため、尺のぶんだけ時間がかかります
- スクロール動画の解像度はビューポート相当です（Playwright の録画機能を使うため、静止画のような Retina にはなりません）
- 頭の切り落としは数百 ms の誤差があります
- スクロール動画は無音です（枠付けツールは元の音声を残します）
- ジョブはサーバー再起動で消えます。ダイジェストの引き直しは同じセッション中のみです
